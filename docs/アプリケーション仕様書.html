Excel Git Diff Viewer

Excelファイルの「値」「数式」「VBAマクロ」を抽出し、Gitのコミット履歴やワークツリー間の差分を、人間が見やすい形で視覚化・比較するWindowsデスクトップアプリケーション。

対象形式　.xls / .xlsx / .xlsm 基盤　.NET 8 / WPF 統合　git difftool 配布　Velopack 自動更新

改訂版で変えたこと

初版の技術選定を実ライブラリの機能に照らして検証し、成立しない組み合わせを差し替えました。

初版ExcelDataReader ＋ ClosedXML で「.xls対応＋数式抽出」
➜
改訂NPOI に一本化（.xls/.xlsx/.xlsm ＋ 値＋数式）
初版VBA抽出に olefile（Python）を併用
➜
改訂C#ネイティブ（OpenMcdf＋MS-OVBA展開）に統一
  • 行・列の挿入/削除検知に 行アライメント方式 を明記（同一座標比較だけでは全行ズレ誤検知が起きるため）
  • 一時ファイルの形式判定を マジックバイト方式 に（git difftool が渡す一時ファイルは拡張子が失われうるため）
  • 配布・自動更新（Velopack）とコード署名方針を仕様として追加

§1プロジェクト概要

1.1開発の背景と目的

Excelファイルはビジネスや開発の現場で広く利用されていますが、バイナリ形式であるため、Git標準の差分表示（git diff）では「Binary files differ」としか表示されず、具体的な変更箇所の追跡が困難です。本プロジェクトでは、Excel内の「値」「数式」「VBAマクロコード」を自動抽出し、Gitのコミット履歴やワークツリー間での差分を視覚的・直感的に比較できるWindowsアプリケーションの開発を目的とします。

1.2キーコンセプト

  • 人間にとっての見やすさ　表形式（グリッド）での直感的な左右比較（Side-by-Side）。
  • エンジニアフレンドリー　git difftool としてシームレスに統合し、コマンドラインから即座に起動可能。
  • 完全な追跡性　表面的な値だけでなく、裏側の「数式」や「VBAマクロ」の変更も逃さず検知。
  • 配布のしやすさ　受け取った人が説明書なしでセットアップ・利用でき、更新も自動で届く。

2.1ライブラリ選定の補足（初版からの変更理由）

  • ExcelDataReader を不採用にした理由　ストリーム型で軽量だが、返すのは数式の計算結果（キャッシュ値）のみで、数式文字列（=SUM(...)）を取得できない。中核要件「値と数式の分離抽出」を満たせない。
  • ClosedXML を主軸から外した理由　数式は取得できるが .xls（Excel 2003以前）に非対応（.xlsx/.xlsm 専用）。要件「.xls対応」を満たせない。
結論上記2つの組み合わせでは「.xls の数式比較」が原理的に成立しない（一方は値しか読めず、他方は .xls を開けない）。すべての形式で値・数式を扱える NPOI への一本化が最も確実かつシンプル。

§3機能要件

3.1Excelデータ抽出機能

  • 値と数式の分離抽出　NPOIのセルから、計算結果の値と CellFormula（=SUM(A1:A10) 等）を同時に取得。
  • 全形式への対応　.xlsx / .xlsm に加え、レガシーな .xls も NPOI の単一APIで読み込む。
  • 形式判定　拡張子ではなくファイル先頭のマジックバイトで判定（3.3 参照）。
  • 複数シート対応　全シートをスキャンし、シート単位での比較を可能にする。

3.2VBAマクロ（.xlsm）差分抽出機能

  • vbaProject.bin の C#ネイティブ・デコード
    • vbaProject.bin は OLE複合ファイル（CFB）で、VBAソースは MS-OVBA 仕様の独自圧縮で格納されている（単純なテキストではない）。
    • OpenMcdf でCFBを開き、VBA/dir と各モジュールストリームを取得 → MS-OVBA 展開でソーステキスト化。
    • 標準モジュール／クラスモジュール／Sheet・ThisWorkbook の各ソースを抽出。
  • テキストベースのモジュール管理　抽出コードをモジュール名ごとに保持し、DiffPlex の行単位差分に引き渡す。
  • 位置づけ　アプリ随一の難所のため、フェーズ2の後半（2b）に切り出して実装・検証する。

3.3Git連携・履歴取得機能

  • 過去コミットデータの復元　2つのコミット（例: HEAD と HEAD~1）のハッシュから、該当Excelバイナリをバックグラウンドで一時復元（LibGit2Sharp）。
  • git difftool 起動引数の解決　$LOCAL（変更前）と $REMOTE（変更後）を受け取り、比較画面を自動初期化。
  • 一時ファイルの形式判定（重要）　git difftool が渡す一時ファイルは拡張子を保持しない場合がある。先頭のマジックバイトで判定する。
マジックバイト判定
.xlsx / .xlsm （ZIPコンテナ）   →  50 4B 03 04   "PK.."
.xls           （OLE複合ファイル） →  D0 CF 11 E0 A1 B1 1A E1

3.4差分アルゴリズム＆視覚化（UI）機能

  • Side-by-Side 比較画面　左右分割（左：Older／右：Newer）でスクロールを完全同期。
  • セルレベルの差分ハイライト　値の変更はセル背景を薄黄、数式の変更はインジケータ＋下部詳細パネルで表示。
  • 行・列の挿入/削除（行アライメント方式）　単純な同一座標比較では、1行挿入された時点で以降の全行がズレ「全セル変更」と誤検知する。行内容のハッシュやキー列を用いた 行アライメント（LCS / Myers diff の行版）で対応付け、挿入行を薄緑・削除行を薄赤で表示する。
  • VBA Diff 専用タブ　DiffPlex による行単位の赤/緑ハイライトを表示。
段階導入MVP〜フェーズ1は「同一座標比較」で割り切り、行アライメントはフェーズ2で導入する。

数式変更の表示イメージ（下部詳細パネル）:

− 変更前: =SUM(C1:C10)
+ 変更後: =SUM(C1:C12)

3.5シート単位の差分検知

ワークブック間でシートの追加・削除・リネームを検知し、シートタブに状態（「追加」「削除」「変更あり」）を表示する。

§5git difftool 設定仕様

ビルドしたバイナリ（ExcelGitDiffViewer.exe）をGit環境に登録する手順です。一度設定すれば、以降は使い慣れたターミナルから呼び出せます。

5.1.gitconfig への登録例

~/.gitconfig
[diff]
    tool = excel_diff
[difftool "excel_diff"]
    path = C:/Program Files/ExcelGitDiffViewer/ExcelGitDiffViewer.exe
    # $LOCAL（比較元）と $REMOTE（比較先）を引数で渡す
    cmd = "C:/Program Files/ExcelGitDiffViewer/ExcelGitDiffViewer.exe" "$LOCAL" "$REMOTE"
[difftool]
    prompt = false
補足受け取る一時ファイルは拡張子を持たない場合があるため、アプリ側は拡張子に依存せずマジックバイトで形式を判定する（3.3）。ディレクトリ一括差分（git difftool -d）は当面の対象外（将来検討）。

5.2コマンドラインからの使用イメージ

bash
# 特定Excelファイルの最新コミットとの差分を確認
$ git difftool budget.xlsm

# コミット main と feature-vba 間の sample.xlsm の差分を確認
$ git difftool main feature-vba -- sample.xlsm

§6開発フェーズ・ロードマップ

開発のハードルを下げ確実に完成させるためのスモールステップ計画です。難所（VBA抽出・行アライメント）をフェーズ2内で分離し、リスクを早期に切り分けます。

Phase 1 ・ MVP

最小限のプロトタイプ

引数で受けた2つの .xlsx の「値」だけを左右 DataGrid に背景色付きで表示（同一座標比較）。マジックバイト判定と git difftool 連携の土台もここで通す。

Phase 2a

数式比較 ＋ 行アライメント

NPOIで数式文字列を抽出・比較。行アライメントを導入し、行・列の挿入/削除を正しく検知・ハイライト。

Phase 2b

VBAマクロ比較

vbaProject.bin の C#ネイティブ抽出（OpenMcdf＋MS-OVBA展開）。DiffPlex によるVBAコード差分タブの追加。

Phase 3

パフォーマンス・配布・UX最適化

非同期読み込み（async/await）とUI仮想化。Velopackによるインストーラ・自動更新・リリースノート。git config 自動登録スクリプト同梱、コード署名方針の適用。

§7想定されるリスクと対策

リスク対策
大規模ファイルのメモリ圧迫・性能低下NPOIで対象シートのみ読み込み、DataGrid 行仮想化、読み込み・差分計算の非同期化。読み込み方針はNPOIで一貫させる（ExcelDataReaderのストリーム読みは数式が取れず不採用）。
行アライメントの計算コスト・精度キー列の指定オプションを設け、巨大シートは行ハッシュによるヒューリスティックで対応付けコストを抑える。
VBA抽出（OLE/MS-OVBA展開）の難度仕様が複雑なためフェーズ2bに切り出し、代表的な .xlsm サンプルで段階的に検証。
結合セル・複雑な書式の再現性主目的は「データ（値・数式）の差分検知」。罫線やフォント色などの装飾はあえて無視し実装をシンプルに保つ。
配布時の SmartScreen 警告無署名exeは初回起動で警告が出るため、コード署名証明書の導入か、未署名配布＋初回回避手順の案内かを方針決定（§8）。
異常系ファイルパスワード保護（暗号化）・破損・空ファイルを検知し、解析不可の旨を明示表示する。

§8配布・自動更新仕様

初版の「その他要望」（説明書なしで即セットアップ／自動更新通知＋更新／リリースノート表示）を、Velopack を用いて以下の仕様として実現します。

  • インストール　Velopack が生成する Setup.exe をダブルクリックするだけで完了（説明書不要）。
  • 自動更新チェック　起動時にバックグラウンドで更新を確認。更新元は GitHub Releases または社内ファイルサーバ/共有フォルダを選択可能。
  • 更新通知＋ワンクリック更新　更新があれば通知し、差分（デルタ）ダウンロードで適用。
  • リリースノートのモーダル表示　更新後（または初回起動時）に、Releases本文または同梱 CHANGELOG からノートを表示。
  • コード署名方針（要決定）　証明書を導入して警告を出さない構成を推奨。コスト判断で未署名とする場合は初回の SmartScreen 回避手順を案内する。

§9補足

9.1対象外スコープ（明示）

  • 罫線・フォント色・セル書式などの装飾の差分
  • チャート／ピボットテーブル／条件付き書式の差分
  • 暗号化（パスワード保護）ファイルの中身解析
  • git difftool -d によるディレクトリ一括差分（将来検討）

9.3テスト戦略

  • 差分エンジン（セル比較・行アライメント・VBA差分）は単体テストの価値が高い。
  • 比較用の小さなサンプルペア（値変更／数式変更／行挿入・削除／シート追加・削除／VBA変更）を .xlsx / .xls / .xlsm で用意し、回帰テスト化する。
