§1背景と現状

ExcelGitDiffViewer は v0.3.0 まで「Excel の Git 差分を GUI で見る」というコア価値が確立しており、 NPOI + DiffPlex + LibGit2Sharp + OpenMcdf + Velopack のスタックで MVP → 数式比較 → 行アライメント → VBA差分 → 非同期化 → Velopack 自動更新まで着実に積み上がっている。

1.1コードベース調査で判明したギャップ

  • 操作性の穴 — XAML に KeyBinding が一切存在せず、検索・エクスポート機能もない
  • レビュー体験の未完成 — レビューモードはあるがコメント記入・状態永続化なし、追加/変更/削除の個別フィルタもない
  • 入り口の弱さ — ホーム画面はあるが「最近開いたファイル」「お気に入り」がない
  • 書式差分が未対応 — セル背景色・フォント・罫線などの見た目の差分を拾えない
  • ローカライズ・アクセシビリティ — 日本語ハードコード、AutomationProperties 未設定
この提案書の使い方 本書は実装確定計画ではなく 提案リスト。優先順位を決めて実際に着手する提案は、 本書をベースに個別の実装プランを起こす前提としている。

§2優先度A・UX底上げ（低コスト・大効果）

いずれも工数が小さく、既存アーキテクチャに素直に載る。導入すると体感 UX が段違いに向上する。次期リリース(v0.4.0)の中心候補。

Priority A

A-1キーボードショートカット

工数 S
何をF3/Shift+F3 で次/前の差分、Ctrl+F 検索、Ctrl+O ファイルを開く、Ctrl+H ホーム、Ctrl+R レビュー切替、Ctrl+1/2/3 ビュー切替、Alt+←/→ シート切替
なぜ現在 XAML に KeyBinding が皆無。差分ジャンプは「▲前/▼次」ボタンのみで、慣れると絶対にキーボードから叩きたくなる操作。
実装MainWindow.xaml の <Window.InputBindings> に KeyBinding を追加し既存の MoveToDiff() / MoveToVbaDiff() にバインド。

A-2差分内検索

工数 M
何をCtrl+F で検索バー、シート内のセル値/数式でヒットする箇所をハイライト＋ジャンプ、シート横断オプション。
なぜ1万行の Excel で「顧客ID 12345 の行の変更を見たい」が現状不可能。レビュー体験の最大のボトルネック。
実装検索バーを MainWindow.xaml ツールバーに折りたたみで追加。ViewModel に SearchQuery / SearchResults / CurrentMatchIndex、ヒットは DataGrid.ScrollIntoView + セル選択で表示。

A-3最近開いたファイル / 最近使ったコミット

工数 S
何をホーム画面に「最近開いた比較」を最大10件表示、クリックで即比較。左右ファイルパス、Git 比較はリポジトリ+2つの SHA を保存。
なぜ現状ホームは「ファイルを開く / Git から開く」の2ボタンのみで殺風景。日常利用の起動時間を削れる。
実装%LOCALAPPDATA%\ExcelGitDiffViewer\recent.json に JSON 保存(System.Text.Json)。ホームXAMLに ItemsControl。

A-4レビュー状態の永続化＆コメント機能

工数 M
何を差分セル・差分行にメモ記入(右クリック→コメント追加)、「確認済み」チェック、状態を左右ファイルペア毎に JSON 保存。
なぜ現状レビューモードはメモリのみ。実務のレビューは中断・再開が前提で「あとで見る」ができない。
実装%LOCALAPPDATA%\ExcelGitDiffViewer\reviews\<hash>.json に「差分位置キー → { reviewed, comment }」を保存。UIは詳細パネルの拡張として実装。

A-5差分種別フィルタ

工数 S
何をレビューモードの隣に「追加 / 変更 / 削除」の3チェックボックス、ONの種別だけ表示。
なぜ現状レビューモードは「全差分」しか出せず、「削除だけ確認したい」「新規行だけ見たい」が頻出ニーズ。
実装SheetTabViewModel.IsReviewMode の隣に ShowAdded / ShowModified / ShowRemoved を追加、_diffLeftRows/_diffRightRows を DiffKind でフィルタ。DiffKind enum は既に完全に揃っている。

§3優先度B・レビュー成果物として使える段階へ

単に「見える」から「共有・記録できる」へ引き上げる帯。v0.5.0 のテーマ候補。

Priority B

B-1差分レポートのエクスポート

工数 M
何を現在の比較結果を HTML / Markdown / CSV で出力。HTMLはセル色付きで社内共有可能、MarkdownはPRコメントに貼れる、CSVは集計用途。
なぜ「レビュー結果をPRに貼りたい」「上長に報告したい」ができない。共有できないと業務プロセスに入り込めない。
実装HTMLは既存 DiffKindToBrushConverter の色を CSS に落とし込んだテンプレートに、シート単位でテーブル生成。出力先は SaveFileDialog。

B-2サマリー / 統計ダッシュボード

工数 S
何をホーム or ツールバーに「変更シートX個 / 追加X行 / 削除X行 / 変更Xセル / VBA変更Xモジュール」のオーバービュー表示。
なぜいきなり明細から入るのは辛い。「全体像把握→気になる箇所へジャンプ」の導線が欲しい。
実装MainViewModel に Summaryプロパティ、SheetTabViewModel.DiffCount(既存)を集計。UIはビュー切替の上部にバッジ形式で常時表示。

B-3セル書式(色・フォント・罫線)の差分

工数 L
何を値が同じでもセル背景色・フォント色・太字・罫線が変わっていたら「書式変更」として検知。
なぜ経理・監査業務では「色を変える=意味的な変更」が多い。NPOIで書式情報は取れるので拾わないのはもったいない。
実装ExcelReader で ICell.CellStyle から FillForegroundColor/Font.Color/IsBold/BorderTop.. を抽出、CellModel にプロパティ追加。DiffEngine に書式比較追加、DiffKind に FormatChanged を追加。
注意差分が爆発しやすい(テンプレを丸ごと塗り替えただけで全セル書式差分になる)ので「書式差分を無視」トグルもセットで用意。

B-4ライトテーマ切替

工数 S
何をヘッダーに ☀/🌙 トグル、Colors.Light.xaml を追加してリソース切替。
なぜダークテーマ固定は好き嫌いが分かれる。特に画面プロジェクタ・印刷スクショではライトが好まれる。
実装App.xaml にLight用ディクショナリ追加、ThemeResources で動的に MergedDictionaries を差し替え。ThemeResources.Brush() と Colors.Dark.xaml の設計はライト対応前提の作り、ペア追加するだけ。

B-5ブランチ間比較＆コミット履歴の拡張

工数 M
何をCommitPickerWindow にブランチセレクタ、任意の2ブランチの HEAD 比較、および100件超のコミット履歴(ページング or「もっと読む」)。
なぜ現状「同一ブランチのコミット履歴100件」しか選べない。feature/foo と main の HEAD 比較は実務最頻出ケース。
実装GitService.GetBranches()(repo.Branches) を追加、CommitPickerWindow にブランチドロップダウン。100件制限は撤廃 or LoadMore ボタン化。LibGit2Sharp は完全対応済み。

§4優先度C・差別化機能

工数は大きいが、他社ツールでも実現が薄く、v1.0.0 の "この製品でないと駄目な理由" を作る帯。

Priority C

C-1名前付き範囲 / ピボット / グラフ / 条件付き書式の差分

工数 L
何をシートのセル値以外の Excel オブジェクトの変更を検知。
なぜ実務の Excel は「ピボットの参照範囲を変えた」「グラフの系列を追加した」といった "セル外" の変更が多い。
実装NPOI で名前付き範囲・条件付き書式は取得可能。ピボット・グラフは NPOI の対応が限定的なため、必要なら DocumentFormat.OpenXml を追加導入。

C-2.xls(OLE2) の VBA 対応

工数 S〜M
何を.xls バイナリ形式でも VBA コード差分を拾えるようにする。
なぜ現状は .xlsm(Zip内 vbaProject.bin)のみ対応。歴史あるプロジェクトほど .xls を使い続けているため導入余地が広がる。
実装.xls は本体が CFB 形式なので、Zip 展開をスキップして直接 OpenMcdf で VBA Storage を取り出せる。VbaProjectReader を分岐追加。

C-33-way マージ(競合解決)

工数 L
何をGit マージ競合時に BASE / LOCAL / REMOTE の3ペインで差分を見て、セル単位で LOCAL/REMOTE を選び解決結果を書き出す。
なぜExcel の Git 運用最大の痛点。競合したら「片方を捨てる」しかないのが現状で、これを解決できれば "この製品でないと駄目な理由" になる。
実装git mergetool プロトコル対応、書き戻し用に NPOI の書き込み処理を追加、UIは3列レイアウト。難易度高。

C-4英語ローカライゼーション

工数 M
何を.resxへ日本語文字列を集約し、英語版リソースを追加、CurrentUICulture で切替。
なぜ現状すべて日本語ハードコード。海外拠点や英語話者への展開余地を確保する準備投資。
実装Properties/Resources.resx + Resources.en.resx、XAML/code-behind の文字列を {x:Static properties:Resources.XXX} に置換。機械的だが範囲は広い。

§5優先度D・エコシステム連携

アプリ単体ではなく、Windows/GitHub/エディタ側からの入口を用意する帯。

Priority D

D-1コンテキストメニュー統合

工数 S
何をExplorer で .xlsx/.xlsm 右クリック → 「Excel Git Diff で開く」を追加。
実装Velopack インストーラに登録スクリプトを組み込み(HKEY_CLASSES_ROOT にキー追加)。

D-2GitHub PR 統合

工数 M
何をPR の Files changed で Excel を検知したら「アプリで開く」プロトコルハンドラ(excelgitdiff://)。
実装プロトコルハンドラ登録＋ブラウザ拡張、または GitHub Actions での PR コメントによる誘導。

D-3VS Code 拡張

工数 M
何を拡張から .xlsx 右クリック → 本アプリに投げる。
実装VS Code 拡張プロジェクトを別途作成し、コマンド経由でアプリを起動。

§6推奨ロードマップ

下記は費用対効果と依存関係を踏まえた推奨順序。実際の優先順位はユーザー判断で自由に組み替え可能。

v0.4.0 · 1〜2週間

短期・体感UXの底上げ

A-1 ショートカット + A-3 最近開いたファイル + A-5 差分種別フィルタ + B-4 ライトテーマ。すべて工数S、既存アーキテクチャに素直に載る。

v0.5.0 · 2〜3週間

中期・レビュー成果物としての価値確立

A-2 検索 + A-4 コメント/永続化 + B-1 エクスポート + B-2 サマリー。「見える」から「共有・記録できる」へ。

v1.0.0 に向けて

長期・差別化ポイントの積み増し

B-3 書式差分 + B-5 ブランチ間比較 + C-1 ピボット/グラフ差分。他社ツールでも対応薄い領域で製品価値を確立。

留意事項 C-3(3-wayマージ)は工数もリスクも大きく、v1.0.0 のフラッグシップ機能として別途プランを切ることを推奨。

§7検証方針

  • 各機能に対応する SampleGen / VbaGen のケースを追加してマニュアル動作確認
    • 例: A-5 フィルタは「追加のみ / 削除のみ / 変更のみ」のサンプルを書き出す
  • GitTest プロジェクトを拡張し B-5 ブランチ比較のヘッドレスチェック
  • WPFのGUI目視確認は自動化不可のため、リリース前にユーザー側で通し動作確認
  • Velopack の自動更新経路は既存の scripts/publish-release.ps1 手順で公開
